# LLM / RAG 총괄 학습 정리

> 학습 범위: 로컬 LLM 환경 구성부터 RAG 검색, 검색 성능 평가, Re-ranking, 최종 답변 생성까지 (24일 차)

## 1. 전체 구조 한눈에 보기

```text
[사전 준비: 문서 색인]
원본 문서 → Chunking(+Overlap) → Embedding(embeddinggemma) → SQLite에 Chunk·벡터 저장

[질문 처리: RAG]
사용자 질문
  ↓
Embedding(embeddinggemma): 질문을 벡터로 변환
  ↓
1차 검색: DB에서 Chunk·벡터 로드 → Cosine Similarity → 후보 Top-K
  ↓
Re-ranking(qwen3:1.7b): 질문 + 후보 Chunk 원문으로 관련성 재평가
  ↓
최종 상위 Chunk 선택
  ↓
답변 생성(qwen3:1.7b): 질문 + 참고자료(Context) → 자연어 답변
```

**핵심:** RAG는 LLM을 재학습시키는 것이 아니라, 질문 시점에 외부 참고자료를 함께 전달하는 방식이다.

## 4. 모델의 세 가지 역할

1. **Embedding 모델**: 질문·문서를 벡터로 변환해 검색을 지원한다.
2. **Re-ranking 모델**: 검색된 후보 문서가 질문에 적합한지 다시 평가한다. 선택 단계이며 전용 Cross-Encoder 또는 LLM을 사용할 수 있다.
3. **생성 LLM**: 질문과 최종 참고자료를 받아 답변을 작성한다.

실습에서는 `qwen3:1.7b`를 재정렬과 답변 생성에 재사용한다. **모델 역할이 세 가지라는 뜻이지, 반드시 서로 다른 모델 세 개가 필요하다는 뜻은 아니다.**

## 5. Chunking과 Overlap

- **문자 수 기반 Chunking**: 구현이 간단하지만 문장 중간이 잘릴 수 있다.
- **문장 기반 Chunking**: 문장 경계를 유지하여 의미 보존에 유리할 수 있다.
- **Overlap**: 인접 Chunk 사이의 맥락 단절을 줄이지만 중복 저장·검색 가능성이 생긴다.
- 정답은 하나의 Chunk 크기가 아니라, **실제 평가 질문에 대한 검색 성능으로 비교**해야 한다.

## 6. 검색 성능 평가 지표

평가 지표는 일반적인 사용자 질문마다 자동으로 계산되는 것이 아니라, **정답지(Ground Truth)가 있는 평가 데이터**에서 측정한다.

| 지표 | 질문 | 공식·의미 |
|---|---|---|
| Hit@K | 상위 K개에 관련 문서가 하나라도 있는가? | 있으면 1, 없으면 0 |
| RR@K | 첫 번째 관련 문서는 몇 위인가? | `1 / 첫 관련 문서 순위`; 없으면 0 |
| MRR@K | 여러 질문의 첫 정답 순위는 평균적으로 좋은가? | `RR 합 / 질문 수` |
| Precision@K | 검색된 K개 중 관련 문서 비율은? | `상위 K개 관련 문서 수 / K` |
| Recall@K | 전체 관련 문서 중 얼마나 찾았는가? | `상위 K개 관련 문서 수 / 전체 관련 문서 수` |
| F1@K | Precision과 Recall의 균형은? | `2 × P × R / (P + R)`; 둘의 합이 0이면 0 |

### 예시

상위 3개 검색 결과가 `[오답, 정답, 정답]`이고, 전체 관련 문서가 총 4개라면:

- `Hit@3 = 1`
- `RR@3 = 1/2 = 0.5`
- `Precision@3 = 2/3 ≈ 0.667`
- `Recall@3 = 2/4 = 0.5`
- `F1@3 ≈ 0.571`
- MRR은 **여러 질문의 RR 평균**이다. 질문이 하나라면 MRR과 RR이 같다.

**중요:** 실습에서 `content.includes(expected)`로 관련성을 판정하는 것은 간단한 대체 방법이다. 실제 평가에서는 정답 Chunk ID 또는 사람이 검증한 관련성 레이블이 더 정확하다. Recall을 계산하려면 전체 관련 문서 수를 알아야 한다.

## 7. Re-ranking 이해

1차 검색은 임베딩 유사도 기준으로 후보를 고른다. Re-ranking은 **질문과 후보 Chunk의 원문**을 보고 다시 관련성을 평가한다.

```text
질문 → 임베딩 검색 후보 10개 → Re-ranking → 최종 3개 → LLM
```

- **Re-ranking 모델에는 벡터값이 아니라 질문 텍스트와 Chunk 원문을 전달**하는 방식으로 실습했다.
- 학습 초기에 사용한 `유사도 × 0.7 + 키워드 점수 × 0.3`은 원리 이해용 휴리스틱이다.
- 실제 실습에서는 Qwen이 문서 관련성을 0~10점으로 평가하도록 요청했다.
- Re-ranking은 **이미 검색된 후보의 순서만 바꿀 수 있다**. 후보에 없는 정답 문서는 복구하지 못한다.
- 같은 후보 10개를 단순 재정렬하면 `Hit@10`, `Precision@10`, `Recall@10`, `F1@10`은 그대로이고 `RR@10`/`MRR@10`은 바뀔 수 있다.
- 최종 상위 3개만 선택해 비교하면 `Hit@3`, `Precision@3`, `Recall@3`, `F1@3`도 달라질 수 있다.
- 일반 LLM을 재정렬에 사용하면 호출 횟수·지연시간이 증가하고 평가 점수가 불안정할 수 있다.

## 8. 최종 답변 생성과 Grounding

검색·재정렬이 끝나면 최종 Chunk를 **Context**로 구성하고 원래 질문과 함께 LLM에 전달한다.

```text
[참고자료]
[문서 ID: 5]
ABC 회사의 근무 시간은 오전 9시부터 오후 6시까지입니다.

[질문]
ABC 회사의 근무 시간은?

[규칙]
참고자료에 있는 내용만 근거로 답변한다.
근거가 없으면 "참고자료에서 확인할 수 없습니다."라고 답한다.
사용한 문서 ID를 표시한다.
```

예상 답변: `ABC 회사의 근무 시간은 오전 9시부터 오후 6시까지입니다. (문서 ID: 5)`

**주의:** 프롬프트만으로 환각이나 잘못된 출처 표기를 완전히 방지할 수 없다. 출처가 실제 주장을 뒷받침하는지 검증이 필요하다.

실습 예시 실행:

```powershell
cd F:\llm-study
ollama list
node src/llm-reranker.ts
node src/rag-answer.ts
```

`rag-answer.ts`는 검색, Re-ranking, 최종 답변 생성을 한 번에 연결한 학습용 코드이다. `qwen3:1.7b`의 응답 형식과 로컬 Ollama 실행 상태에 따라 오류 처리 보완이 필요할 수 있다.

## 10. 검색 품질과 답변 품질의 차이

| 항목 | 검색 품질 | 답변 품질 |
|---|---|---|
| 평가 대상 | 관련 Chunk를 잘 찾았는가 | 최종 답변이 정확하고 근거에 충실한가 |
| 대표 평가 | Hit@K, MRR, Precision, Recall, F1 | 정답 일치, 사실 정확성, 근거 충실도 등 |
| 실패 예시 | 정답 문서가 Top-K에 없음 | 정답 문서를 받고도 틀린 답변 생성 |

검색 성능이 좋다고 최종 답변까지 반드시 정확한 것은 아니다.
