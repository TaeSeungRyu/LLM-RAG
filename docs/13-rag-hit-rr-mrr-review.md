# RAG 검색 평가 복습 — Hit@K · RR · MRR

> 핵심: **Hit@K는 정답을 찾았는지**, **RR은 첫 정답이 몇 위인지**, **MRR은 여러 질문의 RR 평균**을 측정한다.

## 1. 가장 먼저: K의 의미

- `K = 3`은 **질문 하나당 검색 결과 상위 3개 Chunk를 확인**한다는 뜻이다.
- **질문이 3개라는 뜻이 아니다.** 질문은 1개일 수도, 100개일 수도 있다.
- `Top-K`는 검색 결과 선택 설정이고, `Hit@K`와 `MRR@K`는 검색 품질을 평가하는 지표다.

## 2. 용어 한눈에 비교

| 용어 | 의미 | 계산 대상 | 값 범위 |
|---|---|---|---|
| **Hit@K (질문별 Hit)** | 상위 K개 안에 관련 Chunk가 하나라도 있는가? | 질문 1개 | 0 또는 1 |
| **Hit@K (전체 평균)** | 전체 질문 중 상위 K개 안에서 관련 Chunk를 찾은 비율 | 여러 질문 | 0~1 |
| **RR (Reciprocal Rank)** | 첫 번째 관련 Chunk 순위의 역수 | 질문 1개 | 0~1 |
| **MRR (Mean Reciprocal Rank)** | 여러 질문의 RR 평균 | 여러 질문 | 0~1 |

## 3. Hit@K — 찾았는가?

질문: **"ABC 회사의 근무 시간은?"**

| 순위 | 검색된 Chunk | 관련 여부 |
|---|---|---|
| 1위 | ABC 회사는 송도에 있다 | X |
| 2위 | 근무 시간은 오전 9시부터 오후 6시까지다 | O |
| 3위 | ABC 회사는 결제 서비스를 제공한다 | X |

- `Hit@1 = 0` (1위에는 관련 Chunk가 없음)
- `Hit@2 = 1` (2위에서 관련 Chunk 발견)
- `Hit@3 = 1` (상위 3개 안에 관련 Chunk 존재)
- **상위 3개에 관련 Chunk가 2개 또는 3개 있어도 질문별 Hit은 1이다.**
- **Hit@3 = 3은 불가능하다.**

여러 질문의 전체 Hit@K는 질문별 Hit의 평균이다.

`Hit@K = (질문별 Hit의 합) / (전체 평가 질문 수)`

예: 3개 질문의 Hit@3이 `1, 1, 0`이면 `(1+1+0)/3 = 0.6667`.

## 4. RR — 첫 정답이 몇 위인가?

`RR = 1 / 첫 번째 관련 Chunk 순위`

| 첫 관련 Chunk 순위 | RR |
|---|---:|
| 1위 | 1.0000 |
| 2위 | 0.5000 |
| 3위 | 0.3333 |
| 4위 | 0.2500 |
| 관련 Chunk 없음 | 0 |

- 첫 번째 관련 Chunk만 기준으로 계산한다.
- 관련 Chunk가 여러 개 있어도 **첫 관련 Chunk의 순위**만 RR에 반영한다.
- `RR@3`은 **상위 3개 안에 관련 Chunk가 없으면 0**이다. 예를 들어 첫 정답이 4위라면 `RR@3 = 0`, `RR@5 = 0.25`다.

## 5. MRR — 여러 질문의 RR 평균

`MRR = (RR_1 + RR_2 + ... + RR_N) / N`

| 평가 질문 | 첫 관련 Chunk 순위 | Hit@3 | RR@3 |
|---|---:|---:|---:|
| 질문 A | 1위 | 1 | 1.0000 |
| 질문 B | 2위 | 1 | 0.5000 |
| 질문 C | 3위 | 1 | 0.3333 |
| **평균** | — | **1.0000** | **0.6111** |

- `Hit@3 = (1+1+1)/3 = 1.0000`: 세 질문 모두 상위 3개 안에서 관련 Chunk를 찾았다.
- `MRR@3 = (1+0.5+0.3333)/3 ≈ 0.6111`: 찾긴 했지만 첫 관련 Chunk의 순위가 항상 1위는 아니다.

## 6. K를 늘리면 어떻게 될까?

첫 관련 Chunk가 **4위**인 질문이라면:

| 평가 범위 | Hit@K | RR@K |
|---|---:|---:|
| K=1 | 0 | 0 |
| K=3 | 0 | 0 |
| K=4 | 1 | 0.2500 |
| K=5 | 1 | 0.2500 |

**주의:** K를 늘려서 RR@K 또는 MRR@K가 올라갈 수는 있지만, **검색 순위 자체가 개선된 것은 아니다.** 첫 정답을 4위에서 1위로 끌어올려야 실제 순위 품질이 개선된다.

## 7. 실무에서 어떻게 쓰나?

1. 실제 사용자가 물을 만한 질문들을 평가 데이터셋으로 준비한다.
2. 질문마다 어떤 Chunk가 관련 있는지 **정답 기준(Ground Truth)** 을 마련한다.
3. 검색 시스템에서 각 질문의 Top-K를 조회한다.
4. 질문별 Hit와 RR을 계산한다.
5. 전체 질문의 Hit@K와 MRR@K를 비교한다.
6. Chunking, Overlap, Embedding, Hybrid Search, Reranking 등을 조정하고 **동일한 평가 데이터셋으로 재측정**한다.

보통 `Hit@1`, `Hit@3`, `Hit@5`처럼 **K를 고정한 여러 지표**를 나란히 비교한다. 운영 서비스의 검색 Top-K는 고정하거나 질문 유형에 따라 동적으로 설정할 수 있지만, 평가 지표는 비교 가능하도록 동일한 K를 유지하는 것이 좋다.

**주의 사항**
- Hit@K와 MRR은 **검색 단계** 평가 지표이며, LLM이 생성한 **최종 답변의 정확도**를 보장하지 않는다.
- 코사인 유사도 점수는 정답 확률이 아니다.
- 학습 코드의 `content.includes(expected)`는 간단한 임시 정답 판정이다. 실제 평가에서는 정답 Chunk ID 또는 사람이 검증한 관련성 라벨을 활용하는 것이 좋다.
- 상위 K개에 관련 Chunk가 **몇 개** 있는지 평가하고 싶다면 `Precision@K` 같은 지표를 추가한다.

## 8. 암기용 3줄

> **Hit@K:** 상위 K개 안에 정답이 **하나라도 있는가?**
>
> **RR:** **질문 하나**에서 첫 정답이 **몇 위인가?** → `1 / 순위`
>
> **MRR:** **여러 질문**의 RR을 **평균** 내면?

**한 번 더:** `@3`의 3은 **질문 개수**가 아니라 **질문당 확인하는 검색 결과 개수**다.
